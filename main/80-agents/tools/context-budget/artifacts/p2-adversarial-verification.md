# P2-C — Verificación adversarial de `80-agents/tools/context-budget/`

## 1. Alcance y método

- Objeto bajo verificación: la tool context-budget (PHASE 2, implementación P2-B) en `80-agents/tools/context-budget/`: `context_budget.py` (escenarios CTX-01..15), `selftest.py`, `README.md`, y los artifacts `p2-context-budget-design.md`, `p2-context-budget-spec.md`, `p2-implementation-notes.md` y `results/run-*.json`. El Conformance Harness (`80-agents/tools/conformance-harness/`: `rules.py`, `agents_os_conformance.py`) se trata como contrato observable vigente NO bajo verificación; sus defectos se reportan como hallazgos de sistema (S) y no como defectos de la tool.
- Método adversarial: 15 ataques de la lista del encargo más 4 ataques propios; para cada uno se ejecutó lo necesario y se clasificó PASS (no pude demostrar el defecto), FAIL (defecto material demostrado) o UNKNOWN. No se arregló nada; no se lanzaron subagents; no se invocaron MCP tools reales.
- Ejecuciones sobre el vault real (read-only, subproductos aceptados en `results/`): run completo `--json` (run-20260913-044217.json, counts PASS 7 · FAIL 0 · WARN 7 · SKIP 1, fidelity_gate PASS, git_head 1f0d21bf2), run completo desde cwd `/tmp` (run-20260913-044254.json) y `--scenario CTX-14 --live` (run-20260913-044540.json). El selftest se corrió completo: 11/11 PASS reproducido.
- Mutaciones: TODAS en tempdir del sistema (`/tmp/p2c-attack*`), con vault falso que enlaza el harness por symlink y copia las autoridades bootstrap/doctor; ninguna mutación tocó el vault canónico; todos los fixtures fueron eliminados al cierre de cada ataque. Las inyecciones fueron reconstruidas de forma independiente (no se reutilizó el código del selftest T1).
- Convención de severidad propuesta: alta = invalida un veredicto de la suite en condiciones actuales; media = contradice una decisión vinculante del spec/diseño pero no se manifiesta con el modelo actual (`rules.Session`) sin inyección o drift; baja = cosmético/documental.

## 5. Veredicto global de la tool

- **TOOL WITH MATERIAL DEFECTS** — la contabilidad de presupuesto (sets, pesos, etiquetado chars/4, determinismo, cwd-independencia, exit codes, gate, residuo declarado) es sólida y resistió todos los ataques directos de medición; los tres defectos materiales están en la CAPA DE AUDITORÍA de leaks/deprecación/fidelidad (M15/M16 y la re-implementación de los heredados), todos demostrados por mutación en tempdir y ninguno manifestándose con el modelo de sesión actual (`rules.Session`) sobre el vault real de hoy — por eso la suite en verde de los runs reales sigue siendo interpretable, pero las garantías de FAIL que la tool promete (VPN-WARN, deprecated en hot path, herencia completa de asserts) no se sostienen ante sesiones reales o drift del corpus.
- El defecto D1 es directamente contradictorio con una decisión vinculante del parent (A3): el código no puede quedarse así aunque hoy no se dispare.
- D2 y D3 comparten raíz: la re-implementación de los escenarios heredados pierde piezas del contrato que dice heredar; la corrección natural es reutilizar más y re-implementar menos (o restituir los asserts/filtros perdidos con cita al heredado).
