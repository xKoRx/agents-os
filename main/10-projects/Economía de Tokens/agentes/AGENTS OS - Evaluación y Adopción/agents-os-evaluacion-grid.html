1. Veredicto ejecutivo

7.0

AGENTS OS ya no es solo una arquitectura personal: existe un scaffolding compartible, instalación guiada, Graphify portable, higiene periódica y reglas para Codex/Claude. El núcleo es piloto-ready, pero todavía no es estándar de equipo porque faltan la beta comparativa, el benchmark económico y la validación completa por superficie.

✓
Conservar el núcleoMarkdown como fuente de verdad, entidades canónicas, templates, skills explícitas, Context Router y logs auditables forman una base sólida.
⚠
No estandarizar todavíaLa beta E2E comparativa sigue pendiente; no hay evidencia propia suficiente de ahorro neto, continuidad entre superficies ni reducción de reexplicación.
✗
Riesgo vigente: costo operativo no medidoEl cierre explícito y el modo táctico reducen rituales innecesarios, pero arranque, retrieval, memoria, feedback, logs e higiene todavía deben demostrar ahorro neto en tareas comparables.

2. Qué es realmente el sistema

8.4

No es un único prompt ni una base vectorial. Es un sistema operativo documental con gobierno, memoria, recuperación, aprendizaje y una LLM Wiki que compila fuentes en conocimiento canónico mantenido.

  • Memoria: pública auditable, interna privada, journal y entidades canónicas del vault.
  • Comportamiento: constitución, perfil del usuario y 26 skills canónicas bajo 80-agents/skills/.
  • LLM Wiki: fuentes crudas → páginas canónicas mantenidas → 00-index.md curado; es la capa de contenido de Sistema 2.
  • Retrieval: tags/frontmatter → LLM Wiki/índices curados → Graphify AST → cuerpo seleccionado.
  • Aprendizaje: feedback de sesión, feedback de Graphify, Kaizen, destilación, higiene y reindex.
  • Instalación: prompt maestro, entrevista de personalización, descubrimiento de workspaces, reconciliación de aplicaciones y reglas de superficie.
✓
La separación Sistema 1 / Sistema 2 evita mezclar verdad actual con diario de sesiónEs una frontera útil para mantener entidades limpias y conservar trazabilidad.
✓
LLM Wiki es el mecanismo que hace compuesto el conocimientoEn vez de rederivar siempre desde fuentes crudas, el agente integra una vez, actualiza páginas canónicas y mantiene índices curados para recuperación futura.
✓
Ya existe una distribución instalable para el equipoEl scaffolding limpio incluye onboarding, perfil seed, aplicaciones, templates, Graphify portable y un proyecto de instalación completamente abierto para cada integrante.
⚠
El mensaje comercial debe cambiarLa frase “todas las skills usan Graphify” simplifica demasiado: el sistema real es híbrido y depende también de índices curados, búsqueda exacta y lectura quirúrgica.

4. Casos de uso concretos con AGENTS OS

7.6

AGENTS OS aporta más cuando la tarea cruza sesiones, repositorios o agentes y deja conocimiento que vale la pena recuperar. Estos ejemplos muestran el flujo completo y también su límite.

✓
Caso 1 · Retomar un proyecto con un agente frescoEscenario: cambia el agente durante una implementación de Search Middleware o VPP.
Flujo: bootstrap → resolver la entidad canónica → recuperar proyecto, continuidad, decisiones y known errors → abrir solo las fuentes necesarias.
Valor: se retoma ramas, dependencias y decisiones sin reconstruir todo desde el chat.
Límite: la reducción de reexplicación aún no fue medida en la beta formal.
✓
Caso 2 · Diagnóstico cross-repo de una fallaEscenario real: la pill “Bajó de Precio” no aparece y el comportamiento cruza vpp-backend, vis-octopus-lib, search-middleware y SDKs.
Flujo: Context Router clasifica impacto → Graphify path/affected ubica relaciones → notas canónicas y código verifican cada salto → el hallazgo reusable se destila.
Valor: evita investigar cada repositorio como una isla.
Límite: Graphify orienta; git, rg, tests y código siguen siendo la evidencia final.
✓
Caso 3 · Aplicar un guardrail estable sin repetirloEscenario: en repos Meli nunca se deben usar versiones productivas para probar un PR no mergeado.
Flujo: behavior-config clasifica la instrucción → se persiste como preferencia global auditada → futuros agentes la cargan antes de modificar Gradle o consumidores.
Valor: convierte una corrección del usuario en prevención transversal.
Límite: requiere alcance, precedencia y mecanismo de revocación claros.
✓
Caso 4 · Resolver más rápido un error recurrenteEscenario: Graphify devuelve ruido de templates, un CLI cambia o Symphony repite un fallo ya diagnosticado.
Flujo: retrieval por entidad + known_error → síntoma, causa, detección y mitigación → runbook solo si existe una secuencia mecánica validada.
Valor: evita repetir debugging costoso.
Límite: una memoria obsoleta puede acelerar la respuesta equivocada; siempre debe validarse contra la fuente viva.
✓
Caso 5 · Delegar un proyecto retomable a agentesEscenario real: iniciativas de Aranea se dividen en proyectos owner: agent.
Flujo: proyecto hijo bajo agentes/ → tareas internas del agente → una sola tarea puente visible para el humano → bitácora y estados permiten retomar después de un corte.
Valor: separa supervisión humana de ejecución detallada.
Límite: si la nota no se mantiene honesta, se convierte en otro backlog duplicado.
✓
Caso 6 · Mejorar el propio sistema a partir de fricción repetidaEscenario real: varios feedbacks detectan que el cierre completo es demasiado pesado para debug o code review.
Flujo: feedback de sesión → Kaizen agrega patrones → cambio aprobado en la skill → aparece el tactical close.
Valor: la operación real modifica el sistema, no solo la opinión de diseño.
Límite: los scores son escritos por los mismos agentes; hace falta evaluación externa y control.
⚠
Cuándo no usar el circuito completoUna consulta aislada, un cambio trivial o una tarea sin continuidad no justifican full close, nuevas memorias, feedback y reindex. En esos casos basta retrieval mínimo —o incluso búsqueda exacta— y salida compacta.

5. Desventajas y costos de adopción

6.3
✗
Complejidad normativa altaGuía, constitución, perfil, contratos compartidos, 26 skills, templates y memorias crean una superficie grande de reglas que puede competir con la tarea real.
✗
Persistencia obligatoria, aunque no haya valor reusableLa constitución exige tocar memoria interna en toda sesión. Eso favorece crecimiento, sesgo acumulado y escrituras inesperadas en trabajos menores.
⚠
La memoria privada carece de gobernanza de equipoFaltan política de retención, clasificación de datos, revisión, exportación, borrado y controles contra modelos del usuario que se auto-refuercen.
⚠
Portabilidad implementada, todavía no forward-tested en máquinas limpiasYa existen wheel, wrapper, instalador, prompt maestro y configuración por ruta; faltan instalaciones E2E de integrantes y resolver los warnings de versión del runtime de Graphify.
⚠
Cierre mitigado, ahorro todavía no medidoEl baseline de 25 feedbacks deja closeout friction en 3,60/5. Full close ahora exige pedido explícito y existe tactical close, pero falta medir el efecto de esas correcciones.

6. Graphify Obsidian: útil, pero no debe ser el centro

6.6

Reindex local del 14-07-2026: 349 archivos, 3.904 nodos, 4.500 edges, 366 comunidades, 100% EXTRACTED y costo LLM cero. La capa de wikilinks vault-aware funciona, el instalador portable existe y las consultas exactas de entidad son útiles.

  • Rol recomendado: índice estructural derivado por defecto cuando está disponible; reemplazable y nunca autoridad final.
  • Fallback recomendado: índices curados + búsqueda exacta como modo first-class, probado y medido.
  • Mejora inmediata: excluir templates o marcarlos como no recuperables, compactar output y agregar un wrapper único por intención.
✓
Excelente para estructura y relaciones conocidasexplain, path y affected agregan valor cuando la entidad y la relación están bien definidas.
⚠
Baja precisión en síntesis ampliaUna query amplia de arquitectura de AGENTS OS recorrió 311 nodos y se truncó. El reporte vigente confirma 25 comunidades delgadas omitidas y ruido de placeholders, pero ya no respalda la cifra histórica de 2.840 nodos débilmente conectados.
✗
Templates y placeholders siguen dentro del grafoEl reporte actual contiene hubs como {{title}} y las queries todavía pueden arrancar desde plantillas. La mitigación documental no elimina el costo ni el riesgo.
⚠
Operación demasiado específicaSufijo .md, --relation explícita, wrappers distintos, warnings de versión y rutas conocidas son detalles que un usuario de equipo no debería memorizar.

7. Pack de prompts y reglas: hoy es material de referencia, no producto

4.5

El pack Vibe Coding/SDD aparece conectado a AGENTS OS a través de la Resource Wiki, a cuatro o cinco saltos en el grafo. No existe una skill o flujo canónico que lo seleccione, valide y ejecute de punta a punta.

✗
El pack anuncia seis prompts, pero tres están vacíosverify-spec, verify-plan-tasks y verify-implementation solo contienen el encabezado; parte de su lógica está embebida dentro de otros prompts con delimitadores duplicados.
✗
No es realmente agnósticoHay rutas, roles, Symphony, Go, scripts y RFCs hardcodeados. Son playbooks de un repositorio específico presentados como pack general.
✗
Reglas que deben retirarse“Declarar explícitamente Chain-of-Thought” y “proponer siempre Mermaid” agregan exposición y ruido; deben reemplazarse por conclusiones verificables y visuales solo cuando aporten.
⚠
Contradicción de estrategia de contextoCONTEXT_V2 exige whole-document loading, mientras AGENTS OS exige progressive disclosure y body-only. No existe una regla de precedencia por tipo de artefacto.
⚠
TOON todavía es una propuesta no operacionalizadaconfig.toon deja campos incompletos, fija un stack concreto y usa un benchmark teórico de ahorro sin prueba local reproducible.

8. Qué dicen los feedbacks

7.1

La señal acumulada es positiva, pero no equivale a demostrar la tesis completa. Hay 122 feedbacks registrados y una muestra scored útil; muestran continuidad y aprendizaje operativo, pero siguen siendo evaluación producida principalmente por los mismos agentes que usan el sistema.

  • Corpus acumulado: 87 feedbacks de Sistema 1 + 35 de Graphify; baseline scored: 25 feedbacks del 05 al 09 de julio.
  • Startup clarity 4,36/5 · Retrieval usefulness 4,36/5 · Skill fit 4,44/5.
  • Template fit 4,42/5 · Overall confidence 4,58/5 · Closeout friction 3,60/5.
  • El Kaizen previo estimó Graphify en ~3,8/5: alto en código/entidades, bajo en Markdown genérico.
✓
El loop de feedback sí produce aprendizajeCierre táctico, naming de sesiones, caveats de wikilinks y reglas de fallback nacieron de problemas observados.
⚠
Falta independencia de la mediciónLos mismos agentes que usan y evolucionan el sistema escriben los scores; faltan control, tareas comparables y evaluación por usuarios nuevos.

9. Gaps contra la idea principal

5.7
✗
“Entender mejor al usuario en todos sus ámbitos” no está demostradoLa evidencia dominante está en proyectos técnicos Meli/Echo. No hay prueba cross-domain ni evaluación de sesgo o corrección del modelo del usuario.
✗
La beta formal no ocurrióAGENTS OS - Beta y Hardening mantiene abiertas la sesión 1, sesión 2 con agente fresco, comparación multi-superficie y decisión go/no-go; los smoke tests no sustituyen esa evidencia.
✗
No existe benchmark propio de economía totalHay métricas definidas y claims externos, pero no un experimento local que sume tokens, latencia, tiempo humano, closeout, mantenimiento y reindex.
⚠
LLM Wiki está implementada, pero no de forma homogéneaExiste constitución, schema, skill y pilotos vivos en 30-resources; falta medir cobertura, frescura y calidad de integración en todos los dominios antes de presentarla como capacidad completa.
⚠
La fuente canónica mejoró, pero falta enforcement automáticoLas skills viven sólo en 80-agents/skills/ y las superficies apuntan allí sin adapters. Falta lint de autoridad y drift entre constitución, guía, perfiles, índices y clientes.
⚠
La promesa de agnosticismo no está validadaCodex y Claude pasaron smoke tests read-only por nombre contra la fuente canónica. Falta ejecución real, discovery nativo, benchmark y evidencia equivalente para Cursor y Antigravity.

11. Plan de adopción propuesto

8.5

La base instalable ya existe; la siguiente fase debe probar valor antes de estandarizar rituales. Los umbrales siguientes son metas propuestas, no resultados actuales.

  • Estado actual — Base compartible: scaffolding, prompt maestro, instalación, Graphify portable, higiene y skills canónicas listos para piloto.
  • Semanas 1–2 — Piloto: 2 aplicaciones, tareas repetibles, integrantes nuevos, AGENTS OS vs control y al menos Codex + Claude.
  • Semana 3 — Hardening: matriz cross-surface, quiet output/fallback de Graphify, lints de autoridad y data governance.
  • Gate de adopción: ≥70% de retrieval útil; ≥30% menos reexplicación; startup ≤90 s; cierre táctico ≤3 min; cero secretos y cero drift crítico.
  • Decisión: adoptar solo el núcleo que supere el gate; lo demás queda experimental y opt-in.
✓
Qué estandarizar primeroFuente de verdad Markdown, naming canónico, templates, Context Router, logs de cambios y memoria pública reusable.
⚠
Qué mantener opt-inDiscovery nativo, memoria interna privada, cierre completo, prompt packs por repositorio y autoevolución de skills hasta que tengan evidencia.
